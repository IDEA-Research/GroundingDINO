## 1. Product structure
- Route `/` = 一般使用者介面 (dashboard-first). No JSON/PromQL/patch/dev logs/paths ever rendered there unless the developer workspace is unlocked (see section 2) and the user opens it.
- Route `/dashboard/[id]` = headless render for the Playwright evaluator (unchanged contract; DashboardPreview must self-provide TimeRangeProvider when none exists above it).
- Developer workspace = right-side drawer (`DevWorkspaceDrawer`) on `/`, default closed, opened by a 「開發者」 button that is rendered ONLY when `GET /api/capabilities` says `dev_token_configured` and the user has entered the token (sessionStorage `hd.devToken`). Tabs: 「Big Guy」|「規格」|「補丁」|「審查」|「評估」. Resizable (drag handle, min 360px, max 90vw), maximize toggle, Escape closes, role=dialog when overlaying (<lg), focus trap.
- Big Guy button lives in the drawer header AND, when dev is unlocked, the status-bearing 「開發者」 top-bar button shows the CURRENT run status (dot + short label: 待命/排隊/執行中/等待處理/成功/失敗/已取消); historical failures never color the button.
- Helper chat = right-side drawer (`HelperDrawer`) default closed, opened by 「詢問 Helper」 button (top bar + empty states). ChatPanel stays MOUNTED (hidden) so in-flight jobs survive collapse. Below lg: full-height sheet with visible close; never covers the top bar.
- Top bar (`TopBar`): 產品名稱 「Helper Dashboard」, current dashboard name + save state chip (已儲存 / 有未儲存變更 / 尚未儲存), actions: 「開啟」 menu (已儲存儀表板 list with 管理 submenu, 從範本建立, 資料來源狀態), 「儲存」, 「詢問 Helper」, theme toggle (淺色/深色/系統), 「開發者」 (gated).
- Main column order enforced on `/` (not on evaluator route): DashboardHeader (title, description, PatientSelector, DataStatusStrip, TimeRangeControls) -> zone 1 stat_card/gauge -> zone 2 line_chart/bar_chart/heatmap/pie_chart -> zone 3 table/alert_list/decision_flow. Within a zone keep spec (y,x) order.

## 3. Developer execution API (owner: Agent A)
- `GET /api/devfix/config` (dev) -> {project_root, worktree_parent, bin, bin_exists, model, timeout_seconds, runtime_mode, devfix_runtime, local_runs_enabled, auto_fix_enabled, daily_quota:{limit,used}}. Read-only.
- `POST /api/devfix/runs` (dev + kill switch) body {instruction, title?} -> 202 {run_id, ticket_id, status:"queued"|"running"}. Creates a DeveloperTicket (source "manual", auto:false) via the existing ticket store, then enqueues. Queue: in-process FIFO, max 5 pending, one active (reuse auto_fix single-flight lock); queued runs get a run dir immediately with status "queued" so they appear in history. Daily quota applies. `extend_gate.check_user_message_safety` is advisory (record `safety_flags` in meta; do not block unless it already blocks auto-fix).
- `POST /api/devfix/runs/{id}/cancel` (dev) -> 202. Runtime records {pid, pgid} in meta at spawn; cancel sets a flag + SIGTERM pgid, 8s grace, SIGKILL. Finish status "cancelled", error_kind "user_cancel". Cancelling a queued run = remove from queue -> "cancelled".
- `POST /api/devfix/runs/{id}/retry` (dev + kill switch) -> new run with the same instruction, meta.parent_run_id, attempt=n+1. Refused 409 while another run is active.
- `GET /api/devfix/runs` -> {runs:[meta...]} newest first (limit 50). `GET /api/devfix/runs/{id}?after=N` unchanged shape + meta. NEW `GET /api/devfix/runs/{id}/events?after=N` -> {events:[scrubbed event dicts], next_cursor}. NEW `GET /api/devfix/runs/{id}/diff` -> {patch: str (unified diff incl. untracked files as new-file diffs), files:[{path, additions, deletions, status}]}.
- meta.json additive fields: source ("auto"|"manual"), title, instruction (full, scrubbed), parent_run_id, attempt, pid, pgid, queued_at, files_read[], files_changed[] (from tool events + collect_changes on ALL terminal states), tests:{ran:bool, passed:int|null, failed:int|null, summary:str|null} (parse pytest/npm/tsc outputs from bash tool results + report fields), applied:{status:"applied"|"not_applied"|"violation"|"n/a", files:[]}, verification:{status:"passed"|"failed"|"none"}, failure_summary (short), report_status (resolved|rejected|needs_context|failed|timeout|cancelled).
- Status vocabulary (meta.status): queued | running | waiting (needs_context/rejected — Big Guy asks the developer) | success (resolved + applied) | failed | cancelled | timeout. Frontend labels: 排隊/執行中/等待處理/成功/失敗/已取消/逾時; idle = 待命.
- Redaction `_scrub`: exact values of env secrets present in os.environ whose NAME matches /(KEY|TOKEN|SECRET|WEBHOOK|PASSWORD)/ + shapes (sk-..., Bearer ..., discord webhooks, key=value assignments) -> "[REDACTED]". Applied to events.jsonl, log.txt, instruction, diff payloads. Keep paths/commands/test output.
- Agent permission file `.opencode/agent/big-guy-developer-fix.md`: edit allow globs -> `**/frontend/widget-toolkit/**`, `**/frontend/lib/renderer.tsx`, `**/frontend/lib/spec-schema.ts`, `**/backend/app/services/browser_evaluator.py`, `**/tests/**` (keep `"*": deny` FIRST); bash: remove `node *`; allow `python3 -m pytest*`, `pytest*`, `npm test*`, `npx tsc*`, `npm run build*` only. Update tests that pin the allow-list accordingly (they only assert deny-first + deny list; add an assertion that `node *` is absent).
- Auto-fix from chat (LD-2) stays; such runs have source "auto" and are labelled 自動 in UI.

## 4. Data & library contracts (owner: Agent B)
- `POST /api/dashboard/query` request additive: `filters?: {patient_id?: string, device_model?: string}` (label equality applied to result series BEFORE collapse; series lacking the label are dropped when a filter is set), `queries?: [{key, promql, label?, unit?}]` (table widgets only; when present `promql` may be omitted), `join_label?: string` (default "patient_id").
  Response additive: `freshness: {sample_ts: int|null, age_seconds: int|null, stale: bool, budget_seconds: int}`, `step_seconds`, `filters_applied`, `series_labels: [{patient_id?, device_model?}]` (distinct label sets seen), `simulated: bool`, `sim_scenario: str|null`, and for `queries` tables: `table: [{labels:{...}, values:{key: number|null}, ts:{key: int|null}}]` + `columns: [{key,label,unit}]`.
  sample_ts: derive raw metric names from promql via the MetricCatalog list (regex match of known names) -> run `max(timestamp(<metric>))` (instant, at `end`) -> max over metrics; null if none. Staleness budget = env HELPER_DASHBOARD_STALE_AFTER_SECONDS (default 120) but never below 2 x step. `data_status` stays ok|empty (stale is a flag).
  Points: emit `null` value entries where consecutive Prometheus samples are farther apart than 2 x step so charts show gaps (points: [{t, v: number|null}]).
- `GET /api/dashboard/label-values?label=patient_id&hours=24` -> {values:[...]} (Prometheus label values API scoped by time; validate label against an allow-list {patient_id, device_model}).
- `GET /api/datasource/status` (public, booleans/timestamps only) -> {backend_ok, prometheus:{reachable, url_host_only}, exporter:{job:"nicu_jetson", health:"up"|"down"|"unknown", last_error_short}, clinical_metrics_present:[names], last_sample_ts (max over patient_* metrics), age_seconds, freshness_budget_seconds, simulation:{active, scenario}}.
- Simulation (dev-gated): env HELPER_DASHBOARD_ALLOW_SIMULATION=1 + `POST /api/dev/simulation {scenario: off|normal|nodata|stale|partial|offline|error}` (Depends(require_dev)); `GET /api/dev/simulation` (dev). When active, `/api/dashboard/query` returns deterministic synthetic data (reuse `backend/app/prometheus/neonatal_sim.py` generator where possible) with `simulated:true, sim_scenario`; scenario semantics: normal = all ok (2 patients P-01/P-02 with plausible HR 120-160 bpm, SpO2 92-99%, rSO2 60-80%); nodata = empty; stale = ok but freshness.stale=true (sample_ts = now-900); partial = every other patient/column null; offline = raise PrometheusUnavailable (502 path); error = 400 bad query path. Datasource status reflects simulation. Never on by default; state in-process.
- Saved library: `PATCH /api/saved_dashboards/{id}` {name?, description?, tags?}; `POST /{id}/duplicate` -> new entry "{name} 副本"; `DELETE /{id}` becomes soft delete (deleted_at) -> list excludes; `POST /{id}/restore`; `GET ?include_deleted=1` (only honoured with a valid dev header; default excludes). Saved id stable. Register both '' and '/' forms where a collection route exists.
- Templates: `GET /api/templates` -> {templates:[{id, name, description, widget_count, metrics}]}; `POST /api/templates/{id}/instantiate` -> {dashboard: DashboardSpec} (fresh dashboard_id, persisted via DashboardStore.save_dashboard). Built-ins (JSON files under backend/app/templates/): `hr-spo2` 心率與血氧監測 (stat HR, stat SpO2, line HR, line SpO2, table 各病患一覽 using `queries` [HR, SpO2] joined by patient_id), `rso2` 腦部血氧 rSO2 監測 (left/right stats + lines), `vitals-overview` 生命徵象總覽. Metric names from catalog (patient_heart_rate_bpm, patient_spo2_percentage, cerebral_rso2_left_percentage, cerebral_rso2_right_percentage). `thresholds: []` everywhere (no clinical invention). Titles contain NO time ranges. NO stat_card+gauge duplicates. Must validate through the existing spec validator.
- Threshold model: `Threshold` gains optional `direction: "above"|"below"|null`. Effective direction resolver (shared Python + TS helper, identical logic): explicit field; else if >= 2 thresholds and the threshold with the more severe color (red > amber/orange > yellow > other, by hue/name) has the LOWER value -> "below"; else if any label contains "<" or "≤" or "低於" -> "below"; else "above". Rendering: state text label (threshold.label or 高於上限/低於下限) + icon, never color alone. widget_schema_doc + helpercode prompt document `direction`.
- WidgetSpec additive: `queries: list[QuerySpec] | None` (table only, max 6; QuerySpec gains optional `key` and `label`), validated: a table may have `queries` and then `query` becomes optional. spec-schema.ts mirrors (Agent C adds the TS side).
- Orchestrator: (1) title normalizer strips trailing time-range parentheticals `（過去 ...）|(過去 ...)|(last ...)|（最近 ...）` from range-widget titles after generation/patch; (2) prompt rules (bin/helpercode generate/patch prompts + mock defaults): no time ranges in titles, no stat_card+gauge for the same promql, use `queries` for multi-metric tables, set threshold `direction`; (3) `_maybe_handle_save_answer` guard: only treat as a library name if <= 24 chars AND contains none of 改|加|幫|請|把|看|顯示|刪|換|調|設|新增|移除|範圍|分|小時 AND not ending with ? or ？; (4) user-facing reply strings -> 繁體中文; (5) `POST /api/chat/message` contract unchanged; ChatResponse keeps dev fields (runtime_used etc.) — the frontend hides them in the user UI.
- refresh_interval: accept `ms` server-side but clamp to >= 5s; frontend parser handles ms.

## 5. Frontend architecture
### Tokens & themes (owner C)
- globals.css: `:root` = light theme (soft gray-white canvas #f5f7fa, white cards, dark text), `:root[data-theme="dark"]` = dark blue-gray (canvas #0f172a-ish, surface #172033, edge visible >= 1.3:1 vs surface, text >= 7:1). Theme resolution: `data-theme` set by a tiny inline pre-hydration script in layout.tsx from localStorage `hd.theme` (light|dark|system) else prefers-color-scheme; toggle in TopBar (C provides `useTheme()` in lib/theme.ts; D renders the toggle).
- Token groups (RGB triplets, mapped in tailwind.config.js with <alpha-value>): canvas, surface, surface-2, edge, edge-strong, ink, ink-dim (>= 4.5:1 on surface), ink-faint (captions only, >= 4.5:1), accent (blue #2563eb light / #60a5fa dark) + accent-ink, focus ring, status: ok (green), warn (amber), danger (red), info (blue-gray) — status colors ONLY for status meaning. Data palette (NOT green/amber/red): --data-1 teal, --data-2 violet, --data-3 indigo, --data-4 sky, --data-5 fuchsia, --data-6 slate; vital mapping: HR -> data-1, SpO2 -> data-2, rSO2 -> data-3. Spacing/radius/shadow tokens: --radius-sm 6px, --radius 10px, --radius-lg 14px; --shadow-card subtle. Type: body 14px (text-sm) minimum for CJK, captions 12px, badges 11px Latin-only; numerals: container-query sized `clamp(1.75rem, 9cqi, 2.5rem)` (card root has `container-type: inline-size`) with tabular-nums, mono.
- chart-theme.ts becomes runtime-resolved: `getChartTheme()` reads CSS variables via getComputedStyle(document.documentElement) (memoized per theme; re-read on custom event `hd:theme`). No hex literals except fallbacks.
- Motion: global `@media (prefers-reduced-motion: reduce)` disables animations; `motion-reduce:` variants on pulses.
