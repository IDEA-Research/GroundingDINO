# 使用者規格(2026-09-07)— Helper Dashboard 重整:一般使用者介面 vs 開發者介面

請檢查並改進目前位於 http://localhost:3050/ 的 Helper Dashboard,將產品整理成「一般使用者介面」與「開發者介面」,並保留 Big Guy 作為本機開發助手。
請先閱讀專案結構與既有實作,再直接完成必要修改。沿用現有技術與設計風格,避免無必要地重寫整個專案。以下描述中的問題,請先確認現況;已修好的項目不要重複修改。

## 一、產品定位
Helper:協助使用者建立、理解與調整儀表板。
Big Guy:協助開發者在本機檢查問題、修改程式、執行驗證及查看結果。
Big Guy 顯示程式碼、內部路徑與執行紀錄,是開發者需要的功能,不應直接刪除。請將它整理成按需開啟的開發工作面板,避免長期佔據儀表板空間。

## 二、一般使用者介面
以儀表板為主要畫面,建議資訊順序:儀表板選擇與資料狀態 → 主要量測數值 → 趨勢圖 → 病患表格。
新增或改善:
- 開啟已儲存儀表板、從範本建立、連接資料來源的入口。
- 「詢問 Helper」按鈕,點擊後才展開對話面板。
- 病患/裝置選擇、單位、資料來源與最後量測時間。
- 已儲存/尚未儲存狀態、重新命名、複製及可復原的刪除流程。
- 清楚的輸入框標籤、鍵盤操作、焦點樣式與觸控操作區域。
一般使用者畫面不要出現:原始 JSON、PromQL、補丁、修復紀錄、內部檔案路徑與開發評估工具。將這些資訊保留於開發者介面,而不是刪除底層能力。

## 三、Big Guy 本機開發工作面板
保留一個清楚可辨識的「Big Guy」按鈕。點擊後開啟可收合、可調整大小的側邊面板或工作抽屜;需要時可放大。互動方式參考 OpenCode 類型的開發工作區,但不要求完全複製其外觀。
面板應包含:任務輸入區;執行前的任務說明、目標專案與工作目錄;明確的「在本機執行」按鈕;任務狀態:待命、排隊、執行中、等待處理、成功、失敗、已取消;即時進度、工具呼叫與輸出紀錄;已讀取與已修改的檔案;程式差異檢視;測試與檢查結果;任務歷史,以及失敗原因摘要;取消任務與針對失敗任務重新執行的操作。
行為要求:
- 開啟面板只顯示資訊,不自動啟動任務。由使用者按下執行按鈕後,才啟動本機開發流程。
- 任務執行中即使收合面板,也能從按鈕看到狀態。
- 清楚區分目前任務與歷史任務,避免舊失敗紀錄看起來像目前網站故障。
- 長篇紀錄可搜尋、篩選及展開;預設先呈現摘要。
- 有修改不代表成功,必須分別呈現修改、驗證及套用狀態。
- 不得透過替代工具繞過被拒絕的檔案或指令權限。
- 機密值應遮蔽,但保留開發者需要的診斷資訊。
優先沿用專案既有的本機執行服務與 OpenCode 整合。若尚未整合,先確認可用介面,實作明確的執行層;不可用假紀錄或假成功狀態代替真正執行。
瀏覽器應透過受限制的本機服務啟動任務,不要建立任何人都能呼叫的任意指令執行入口。

## 四、區分使用者與開發者功能
可共用元件與程式碼,但必須區分使用者功能與開發能力。
- 本機開發環境提供 Big Guy 與完整診斷工具。一般使用者部署不提供本機執行能力。
- 如採用角色權限,必須在伺服器端驗證;不能只靠隱藏按鈕或前端模式切換。
- 既有「規格/補丁/審查/評估」整合進開發工作區,避免多個常駐面板互相擠壓。

## 五、修正已觀察到的資料與介面問題
1. 連線正常但所有元件無資料:分別顯示伺服器連線、資料接收狀態、最後查詢時間與最後量測時間。不能把查詢成功解讀為已有有效量測。
2. 缺少資料時沒有下一步:區分載入中、尚無資料、來源離線、資料過期與查詢錯誤。提供對應的檢查資料來源、重新載入或調整時間範圍操作。使用者版顯示易懂說明,技術細節放進開發者診斷。
3. 時間範圍與標題不一致:選擇「5分」後,圖表標題、查詢範圍及顯示內容必須一致。時間範圍採單選語意,並將時間範圍與自動更新控制清楚區分。
4. 表格內容與名稱不一致:確認「各病患心率與血氧一覽」同時取得兩種量測,依 patient_id 正確配對。顯示清楚的欄位名稱、單位及時間;缺值不可當作零。
5. 首頁空白提示不準確:已有儲存項目時,提示選擇儀表板或恢復上次開啟項目。真正沒有任何儀表板時,才顯示首次建立引導。
6. 圖表門檻值:歷史修復紀錄曾提到折線圖門檻值問題,請確認目前是否仍存在。檢查折線圖、數值卡與儀表圖是否正確解讀既有門檻設定,包括高於/低於的判斷方向。不要自行發明或更改臨床門檻值。

## 六、響應式版面與資訊精簡
- 手機不可維持四張數值卡擠在同一列。小螢幕每列一至兩張卡片,趨勢圖佔滿一列。
- 對話及 Big Guy 面板不得遮住必要操作。電腦版讓儀表板獲得主要寬度,側邊工具按需開啟。
- 改善文字截斷、次要文字對比與按鈕大小。
- 檢查重複的數值卡與儀表圖,預設呈現最有用的組合;保留有不同用途的視覺化。
- 將名稱旁容易誤觸的刪除「×」改為有明確文字的管理選單。

## 七、驗證與交付
使用測試資料驗證正常、無資料、錯誤、過期與部分缺值情境;模擬資料必須明確標示。
完成必要檢查:手機、平板及桌面版面;時間範圍與查詢、標題的一致性;心率與血氧資料配對;儀表板儲存、重新載入與刪除復原;Big Guy 的啟動、進度、取消、失敗呈現及重新執行;一般使用者無法呼叫開發執行功能。
完成後提供:1 實際修改項目與目的;2 使用者介面與開發者介面的入口;3 Big Guy 本機執行的操作方式與必要設定;4 已執行的驗證與結果;5 尚未完成或因環境限制無法驗證的部分。
不要將未驟證的功能描述為已完成。

# 第二部分:一般使用者版本視覺與互動重新設計(直接實作)
保留繁體中文,改善資訊層級、排版、配色、間距與操作體驗。

## 一、設計方向
簡潔的專業監控介面:清楚的文字層級、舒適的留白、一致的卡片/按鈕/圖示、適量圓角、細緻邊框及輕微陰影、克制裝飾讓資料成為重點。
避免大面積漸層、霓虹光暈、過度玻璃效果、巨大宣傳標語、沒有用途的裝飾圖表。

## 二、頁面配置(桌面)
- 頂部:產品名稱、目前儀表板及必要的全域操作。
- 主內容上方:標題、簡短說明、病患/裝置選擇與資料狀態。
- 第一區:重要量測數值。第二區:趨勢圖。第三區:詳細資料表。
- Helper 以清楚的按鈕開啟側邊面板,預設收合。
只在確實存在多個主要頁面時使用側邊導覽。一般使用者版不顯示 Big Guy、規格 JSON、PromQL、補丁或開發紀錄。

## 三、配色與文字
建立統一的設計 token(背景、文字、邊框、間距、圓角、狀態色)。
- 淺色主題:柔和灰白背景、白色卡片、深色文字。深色主題:深藍灰背景,卡片與底色明確區別。
- 藍或青為主要互動色。綠、黃、紅保留給明確的狀態意義。不可僅靠顏色表示異常,需搭配文字或圖示。
- 中文內文 14–16px;主要數值 28–40px。次要文字容易閱讀。數值使用等寬數字,更新時避免版面跳動。

## 四、量測卡片
量測名稱 → 主要數值 → 單位 → 資料時間/狀態。
- 單位與數值明確層級。比較變化僅在有足夠資料且基準清楚時顯示;不預設上升是好事。
- 無資料顯示「—」與原因,不可顯示 0 或正常狀態。
- 避免相同資料以數值卡和儀表重複佔據主要空間。技術說明移至可開啟的詳細資訊。

## 五、趨勢圖與表格
趨勢圖:清楚標示時間軸、單位與圖例;網格低干擾;提示可辨識時間/對象/數值;資料缺口如實呈現不任意連線;時間範圍切換後標題與內容同步;門檻線用既有設定。
表格:欄位名稱易懂繁中;數值/單位/時間/狀態排列一致;必要的搜尋、排序與空白狀態;手機版優先顯示重要欄位,其餘可展開。

## 六、完整的狀態設計
首次使用、載入中、正常、尚無資料、部分缺值、資料過期、來源中斷、查詢失敗、儲存成功與失敗。
訊息簡短具體、必要時提供下一步。避免每張空白卡片重複大段錯誤文字。載入用骨架畫面;背景更新保留既有內容並標示更新狀態。

## 七、響應式與互動
桌面多欄;平板減欄;手機每列一至兩張量測卡,趨勢圖各佔一列;不可整體縮小。觸控區域足夠;鍵盤操作、可見焦點、prefers-reduced-motion。動畫短暫細微。不新增沒有實際功能的按鈕、數字、通知或選單。

## 八、交付要求
先以目前的心率與血氧儀表板完成一套一致的視覺設計,再整理成可重用元件。以明確標示的模擬資料檢查完整畫面,也驗證真實無資料情境。
完成後:實際檢查桌面、平板與手機畫面;修正文字截斷、重疊、橫向溢出及對比問題;確認原有功能仍可運作;提供修改摘要、主要畫面截圖與尚未完成項目。
最終成果應讓使用者快速回答:「我正在查看誰的資料?」「最新數值是多少?」「資料是否仍在更新?」「趨勢如何?」「接下來可以做什麼?」
